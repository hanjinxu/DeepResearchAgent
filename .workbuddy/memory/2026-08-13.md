### 关键结论
1. **管线顺序正确**：SFT → DPO → PPO/GRPO，但"SFT效果不行才上DPO"的理解需要修正
   - 每阶段加的是**不同类型的学习信号**：SFT=模仿、DPO=偏好、PPO=端到端reward
   - 不是"上一个不行换下一个"，而是渐进式信号叠加

## 后续补充的设计决策（面试准备）

1. **SFT 样本格式约定**：State 写原始连续值（score 写 0.67 不写"中"），档位（低/中/高）仅用于数据生成时的分层采样，不用离散化进训练数据。阈值锚点用代码现成的 0.6（needs_quality_repair）和 0.8（evaluator"优秀"线）。
2. **SFT 数据规模**：300-600 条起步（LoRA），PASS 占 15-20%；数据源用 DeepSeek 合成（植入已知错误）+ 管线真跑混合。
3. **格式训练**：格式正样本占比 10-15%，格式负样本兜边界（小写pass、PASS带尾巴、超3条、无编号）。
4. **关键改造点**：当前 RED_TEAM_PROMPT 只传 research_brief+draft_report，未传 state。需改 prompt 加 <当前状态> 块、supervisor 写回分数、red_team_node 传 state，否则 SFT 白训。
5. **V1→V2 面试叙事（最终版）**：用户明确 V1 prompt 已含 state+格式要求。故缺陷定位不是"信息没给到"，而是"规则知道了不执行"。核心论证：控制变量（prompt 一字不改只换权重）+ prompt 无法约束输出分布只有权重能。金句："模型'知道规则'不等于'执行规则'"。
6. 用户偏好：纯文本回答，不要可视化。
7. **红队基座模型确定：Qwen3-32B**。SFT bad case 四类定稿：幻觉、引用位置错误、引用原文篡改、策略泛化空洞。训练配置建议：数据 1500-2500 条推荐（32B 比 7B 需略多）、LoRA r=16~32/alpha=2r、lr=2e-4、3epoch、bf16、max_len 4096、关闭 Qwen3 thinking 模式；A100 80G 单卡约 30-60min/2000条，4090+QLoRA 约 2-4h。
8. **关键方法论澄清**：bad case 是负样本，不能直接进 SFT（SFT 只学正样本）。正确做法是"为每个 bad case 构造正样本镜像"（同一 State+草稿，把错误输出换成正确输出）。bad case 本身不浪费——留到 DPO 当 rejected，与正样本镜像组成 (chosen, rejected) 对。4 类 bad case 只是"批评质量"维度，还需补状态感知类 + 格式类正样本。
9. **DPO 配置**：LoRA（非全量），500-1500 对（hard negative 为主），β=0.1、lr=5e-6~1e-5、1-2 epoch、r=16；4×A100 80G 约 10-20min/1500对/1epoch。reference model = SFT 合并后的模型。
10. **上 PPO/GRPO 的理由（用户从日志发现）**："局部 vs 全局"批评策略差异——局部策略每轮贪心找新问题（1轮抓数据错误、2轮抓结构缺失）；全局策略第2轮深挖 A 的根因，轨迹级提升更大。核心论点：SFT/DPO 是单步（point-wise）优化，学不到轨迹级策略；只有 GRPO 用 trajectory-level reward（episode 最终 score / 累计 Δscore）才能学会"深挖根因"这种高杠杆行为。**reward 设计坑**：必须用轨迹级 reward，不能用单轮 Δscore（否则仍学到局部最优白训）。
