# 2026-10-08

## 面试 JD 对照（重要澄清）
- 用户面试「大模型算法工程师（Agent 后训练）」，我做了本项目 vs JD 的覆盖度分析。
- **关键澄清（纠正我此前的误判）**：本项目 Deep Research Agent 的主后训练链路是 **SFT → DPO → PPO 三级**，**不是 GRPO**。之前 grep 到 llm.py/search_factory.py 里的 "grpo" 是另一条线（多轮搜索奖励设计讨论），主训练落地用的是 PPO。
- 完整后训练方案（用户亲述的权威事实）：
  - **SFT**：5000 条，修红队批评 bad case（幻觉/引用错位/篡改/套话），65→70 分。
  - **DPO**：500 对偏好对，压 SFT 后残留 bad case；关键经验「rejected 和 chosen 越像越好，别用明显垃圾当 rejected」；LLaMA-Factory 4 卡 1h，lr=5e-6 + beta=0.1 + 1 epoch。
  - **PPO**：500 prompt（0~10 批评/条，共 ~5000 次），epoch=2 / bs=32 / 4×昇腾910 / rollout tp=2 dp=2 / train tp=4，verl。奖励三组件：2.0×(final−initial)/(100−initial) + 1.0×ΣΔScore/max(100−score,5) − λ_r·轮次惩罚。critic 冷启动：SFT/DPO 后 policy 跑 30~50 条 rollout，冻结 backbone 只训 value head。
  - **评分模型（舆情报告 judge）**：LLM-as-Judge prompt（事实锚定/风险识别处置/全局一致三块）+ BT 训练，约 12000 偏好对（每场景 ~3000），LoRA，verl。
  - **去噪模型**：片段级清洗（话题/情感错位、主体泛化、纯冗余佐证 4 类），Qwen32B LoRA 30000 条，8×A100 5~6h。
- **为何不用基座大模型**：舆情数据敏感不能出域；私有化部署；Qwen3-32B 与 DeepSeek 准确率 gap 仅 8 个点。
- **为何选 PPO（三级叙事）**：SFT/DPO 是离线单轮，表达不了「第 3 轮转移决策的长期后果」；PPO 用 GAE advantage 把回合末全局收益分解回每轮，配 process reward + 轮次惩罚 + 时序状态 (draft, history)。

## 结论
- 综合匹配度 **85/100**（上轮误判为 55）。剩余缺口：DeepSpeed/Megatron 框架名未对应（可用手算显存补）、GRPO vs PPO 对比需能自圆其说、学历/年限待确认。
