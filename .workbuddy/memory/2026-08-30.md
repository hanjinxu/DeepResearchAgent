# 2026-08-30

## 面试准备：Red Team PPO 设计回答（两版叙事）
- 项目背景：Deep Research Agent 红队 agent 用 PPO 优化（verl-ascend，4×昇腾910）。
- 第 1 版叙事（RL 四层设计框架）：问题定义（序贯决策）→ 状态/动作（draft+history=[(方向,批评,该轮后分数)] 共享）→ 奖励三组件（2.0 结果归一化学全局最优 / 1.0 过程增量解决早期学分分配 / λ 轮次惩罚禁止无意义探索）→ critic 冷启动（SFT/DPO 后 policy 跑 30~50 rollout 取真实 R，冻结 backbone 只训 value head）→ 训练工程（500 prompt×~10轮=5000 批评，batch32，rollout tp2/dp2、train tp4）。
- 第 2 版叙事（用户指定：从 SFT/DPO 效果不够好切入）：SFT(5000条,批评质量 bad case:幻觉/引用错位/篡改/套话)→DPO(500对,残留 bad case,rejected 越像 chosen 越好,单轮到顶)→新瓶颈(批量测试最终分不高但过程分都高→单轮质量已达标、时序方向决策次优)→第一性原理归因(SFT 是 token 级交叉熵、DPO 是单轮序列偏好，信号里都没有回报/延迟奖励，离线单轮学不了在线多轮 credit assignment，堆数据不改变信号粒度)→引入 PPO(唯一带 GAE 学分分配的优化,on-policy)。
- 用户偏好确认：问题驱动叙事优先于架构罗列；先给矛盾现象（最终分低但过程分高）再给方案；SFT/DPO/PPO 三层递进讲"每层解决上一层的残留问题"。
- 关键数字补充：SFT+DPO 后报告分数 65→70（单轮层面到顶的量化证据），PPO 解决 70 分之后的全局时序瓶颈。最终定型四步流程图：① SFT+DPO 达标(65→70) → ② 最终分不高但过程分高 → ③ 归因：离线单轮无回报信号 → ④ 引入 PPO(GAE 学分分配 + 状态/奖励三组件/critic 冷启动)。
- 面试问题："为什么不用基座大模型 API？" → 重构为四维选型框架：① 数据合规底线(舆情敏感不出域) ② 任务适配(模板化填充，瓶颈在检索不在智力，需补内部评测证据) ③ 成本结构(7×24 持续+突发峰值，按量计费不可控：拆成成本/限流/延迟三点) ④ 可靠性(限流/排队/版本变更 vs 自部署 SLA) + 收尾"不是不用基座，是分层分工"(高频模板化→小模型私有化，复杂高难→大模型兜底)。用户原三点回答约 78/100。
- 调研结论（2026-08 核实）：商用大模型 API 数据必过厂商服务器（推理层面不可避免），但训练/留存可用条款锁定——OpenAI/Anthropic/阿里百炼/火山方舟默认不用于训练，留存 30~55 天，OpenAI 有 ZDR 零保留（企业申请）；网页版与 API 是两套政策；DeepSeek/MiniMax 默认可能用（可 opt-out）。风险点在留存窗口、人工审核、跨境司法请求、第三方分包。
- 面试问题补充（"为什么不用基座"第 2 点的高并发数据）：业务形态=每天 top150 热点事件 × 每条跑完整 DeepResearch 多轮 agent。放大链路：150 条/天（固定 SLA 必须跑完）→ × 多轮放大（5~10 轮 × 每轮多次 LLM 调用：子搜索 agent/合并/红队/评分）→ 单条放大 10~50 倍 → 日总量千万级 token（1500~4500 万），且总量波动大（事件复杂度不同）。三个不可控：成本（按量计费∝总 token，峰值账单指数涨）、限流（RPM/TPM 硬上限，突发 1 小时涌入 50 条直接中断）、延迟（高峰期排队 TTFT 变长）；自部署=固定成本+并发自管。待填真实数字：单条平均 token、日总 token、峰值并发数。
