## Deep Research 架构讨论：④ 法务处置建议如何实现
- 核心认知：处置建议不是"检索出来的"，是"决策生成出来的"。搜索只提供③的事实输入（风险类型/等级/主体/时间线），④ 的能力来源是领域规则 + 历史案例 + 法律知识。
- 三层生成架构：
  ① 规则知识库：风险类型 → 必选动作映射（名誉权→证据保全+法律函件；证券信披→72h 公告+监管沟通），保证覆盖不遗漏（呼应评分模型"无悬空风险"维度）；
  ② 案例/法条检索：从历史处置记录建向量库，检索同类型案例 + 法规依据，提供可溯源依据（法务可用性关键）；
  ③ LLM 实例化：动作模板 + 案例 few-shot + 当前事实 → 写出"谁/何时/怎么做"的具体动作（对应红队【建议实施】审查标准）。
- 审查闭环：红队【建议实施】+ 评分【处置建议】→ 不达标打回重写（复用已有多轮迭代体系）。
- 边界设计：动作标注依据引用；高风险输出"需人工复核/暂不介入"——AI 不替代法务判断。
- 面试要点：被问"处置建议是编的吗"→ 答"动作框架来自规则库（专家沉淀），细节由 LLM 基于案例实例化，依据可溯源，高风险人工复核"。
- 面试问题："PPO 遇到什么困难？" → 三大困难（现象→归因→解法→结果）：① 训练早期不收敛 → value head 随机初始化致 GAE 噪声 → critic 冷启动（SFT/DPO 后 policy 跑 30~50 rollout 取真实 R，冻结 backbone 只训 value head）；② 奖励缺陷 → 只用终局分学分分配慢 + 每轮零成本走满轮 → 三组件 reward（结果/过程/轮次，reward shaping 缓解稀疏奖励）；③ 昇腾适配 → vllm-ascend 效果差 → 换 vllm + 显存分项预估（rollout：权重32G/卡 + KV 1GB/条(tp2→0.5G) 容64条→batch32；train：LoRA 后优化器梯度≈0 + 激活 2.68G/条(tp4) →minibatch8；ref/reward 预计算不进训练显存）。验证闭环：策略可解释（涨幅递减+连挖→转移；刚开张+涨幅大→深挖）。追问弹药：reward hacking（评分模型 BT 独立训练+人工校准回流+KL 兜底）、λ_r 启发式+grid search。
