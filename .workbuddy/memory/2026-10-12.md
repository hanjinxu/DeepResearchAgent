## 🆕 事件记忆层落地（判重 + 增量进展追踪 + 归档，2026-10-12 深夜）
新增 `deep_research/memory/` 包（8 个文件）+ `prompts/event_memory.py` + `test_event_memory.py` + `docs/事件记忆层设计.md`。
图结构变为：`START → event_recall → [write_research_brief | write_draft_report] → … → final_report_generation → event_memory_commit → END`

**关键设计决策（面试可讲）**
1. **三级判重漏斗**：L1 实体+议题归一化精确匹配（零模型成本，吃掉"每天重复同一热点"主场景）
   → L2 向量召回 top5（只粗筛）→ L3 LLM 判定（拿不准倾向判否，防错误合并污染报告）。
2. **⚠️ 实测标定（重要，别再凭直觉改阈值）**：hashing-ngram 余弦量纲 —— 同事件换说法 0.35、
   同事件长报告 0.18~0.27、同事件短标题 **0.10**、同主体不同议题 **0.07**（几乎贴在一起）。
   → 结论：**向量分数只能排序，不能判定**；`l2_floor` 默认 0.05（hashing）/ 0.55（真 embedding），
   已加回归断言拦住"凭直觉调到 0.15 以上"的改动。
3. **增量检索**：11 个动作关键词 `回应/声明/辟谣/通报/处罚/整改/起诉/反转/否认/致歉/热搜`
   按 3 个一组 + 2 条时间锚定 = 6 条检索式。**不走网页全文 LLM 摘要管线**，直接取 Tavily 标题+摘要片段
   → 6 条检索式 ≈ 0 次摘要调用（这是增量追踪真正的成本节省点）。
4. **结果归位两槽**：证实/证伪 → 2.2 事实状态机（`unconfirmed→confirmed/refuted`，留迁移历史=辟谣追踪）；
   带时间点新进展 → 1.2 时间线（按 (time,node) 指纹去重）。
5. **ES 不是硬依赖**：`backend: elasticsearch` 连不上/维度未知 → 自动降级 JSONL 并告警；
   两个节点全 try/except，记忆层是增值能力不是必要链路（集成测试已验证"记忆库宕机仍正常出报告"）。
6. **DeepSeek 没有 embedding API** → 默认零依赖 `hashing_ngram`（字符 2/3-gram + hashing trick 到 256 维，
   固定维度可直接落 ES dense_vector）；可选切 `openai_compatible` 指向本地 vLLM 的 Qwen3-Embedding。
7. **increment_mode: full | fast**（默认 full）：
   - full = 仍走完整主循环，但简报收敛到"只补新进展"（省研究范围）
   - fast = 跳过整个 supervisor 主循环直达终稿（省成本，但**报告不经红队与评分迭代**）——这是 trade-off，做成开关交用户拍板

**验证**：`python test_event_memory.py` → 68/68 通过（含节点级集成：首轮建档→二次命中→fast 模式→归档→容错降级→开关直通）。
