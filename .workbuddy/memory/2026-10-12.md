- 现象：`python run_project.py` 跑到 `write_research_brief` 节点崩，栈底
  `httpx2/_decoders.py:191 ... TypeError: process() takes no keyword arguments`
- 定性：**httpx2 库 bug**（把 `output_buffer_limit=` 关键字传给 zlib 的 C 解压函数）。8 个 role 的 backend 均已正确解析为 deepseek，图构建成功 → config 改动生效、DeepSeek 连通，崩在"读响应体解压"环节。
- 修复优先级：① `pip install -U httpx2`；② 直接 patch 源码去掉该 kwarg
  （`F=$(python -c "import httpx2._decoders as d; print(d.__file__)")` 后
  `sed -i 's/, output_buffer_limit=output_buffer_limit//' "$F"`）；
  ③ 兜底 `pip install "openai<2"` 回退到 httpx 体系。
- AutoDL 上项目实际路径：`/root/autodl-tmp/deepresearch/`（非此前建议的 project-Deep_Research）。

## 报错①②③ 的修复（按时间顺序）
1. **① httpx2 brotli TypeError** → `pip install -U httpx2` 无效（已最新 2.13.1），
   实际生效：`pip uninstall -y brotli brotlicffi`（不再走 brotli 解压链路）。

   验证命令：`python -c "from deep_research.llm import get_chat_model; print(get_chat_model('draft').invoke('只回复两个字：你好').content)"`
3. **③ 400 This response_format type is unavailable now** → 命中此前预警的 `supervisor.py:158`
   `with_structured_output(SupervisorDecision, method="json_schema")`（vLLM xgrammar 专用，DeepSeek 不支持）。
   **已修复（2026-10-12）**：改为按后端能力自动降级，不再写死：
   - `_STRUCTURED_METHODS = ("json_schema", "function_calling")`，模块加载时各构造一份链路

   - 效果：DeepSeek / 本地 vLLM 双后端**都无需改代码**，切后端自动选最强可用约束
