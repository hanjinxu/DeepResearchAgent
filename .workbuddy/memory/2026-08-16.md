### Critic 冷启动方案
- verl 默认 critic backbone = SFT checkpoint 初始化，value head 随机，靠高 lr(1e-5) 快速收敛 → 半冷启动
- 额外冷启动：用 SFT policy 跑 30~50 条 rollout 收集 (prompt, return) 对，冻结 backbone 只训 value head
- return = reward 公式最终值，每轮 label 做 gamma 折扣
- 写了两个脚本：coldstart/collect_rollout_data.py + coldstart/pretrain_value_head.py
  - collect: 导入项目 LLM 和 prompt，10 个舆情主题 × 最多 10 轮红队循环，计算 return，保存 rollout_data.json
  - pretrain: 加载 Qwen3-7B，替换 LM head 为 value head，冻结 backbone，5 epoch MSE 训练，保存 checkpoint
- AutoDL 执行步骤：传脚本 → 激活 venv → 确认 vLLM 双实例 → 跑收集 → 跑预训练 → 接入 verl PPO

### PPO 训练时间与显存预估（4卡910B，32B，LoRA）
- 配置：500 prompt，batch=32，epoch=2，32 iteration；rollout DP=2×TP=2，train TP=4
- 总耗时 ~82h（rollout ~64h + train ~16h + sync ~1.5h），费用 ~¥1000
- 单 iteration：rollout ~2h + train ~30min；train 拆解：176条(32×5.5) ÷ mini_batch8 × 4 inner_epoch = 88步 × 4 micro-batch = 352次fwd+bwd × ~3s ≈ 16min(policy) + ~14min(critic)
- mini_batch=每批几条序列算梯度；inner_epoch=同一批数据学几遍（PPO 默认4遍）

### 显存换算（面试要能现场算）
- LoRA 后优化器+梯度从 ~384GB/64GB 缩到 ~2GB，可忽略；大头只剩冻结权重 64GB + 激活值
- KV cache = b × s × (num_kv_heads × head_dim) × layers × 2 × 2bytes，GQA 用 kv_heads(8×128=1024) 不是 hidden_size(5120)，差5倍
- 32B 每 token KV = 256KB（整卡），TP=2 每卡 128KB；s=4096 → 512MB/条/卡；32GB ÷ 512MB = 64条 → batch=32 富余
- 激活值 = b × s × hidden_size × layers × C × 2bytes，C=梯度检查点系数（不开~20，开~4）；10.7GB/条全模型，TP=4 → 2.68GB/卡/条
- 梯度检查点：每层只存1份输入检查点（num_layers 躲不掉），中间20份 backward 时重算，省的是 C 不是 layers
- 训练时显存只有 policy + critic 各16GB（TP=4），共32GB；reference 和 reward(评估器) 都在 rollout 阶段预计算成数据，训练时不再加载
- 剩余 32GB - overhead(3~5GB) ÷ 2.68GB/条 ≈ 10条 → mini_batch=8 刚好
